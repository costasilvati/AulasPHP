7 Validar forms e reutilizar de scripts com include e require em PHP

Códigos desenvolvidos em sala de aula

Neste capítulo, avançaremos no estudo de PHP com foco em dois temas muito importantes para o desenvolvimento de sistemas web: a validação de formulários e a reutilização de código por meio de arquivos externos.

Ao desenvolver aplicações web, não basta apenas receber os dados digitados pelo usuário. Também é necessário verificar se esses dados foram preenchidos corretamente, se estão em um formato esperado e se podem ser utilizados com segurança no sistema. Esse processo é chamado de validação. A validação no servidor é indispensável para garantir integridade e segurança, mesmo quando o formulário já possui validações no HTML ou em JavaScript.

Além disso, à medida que um sistema cresce, torna-se inconveniente repetir os mesmos trechos de código em várias páginas. Um exemplo clássico é o menu de navegação. Em PHP, esse problema pode ser resolvido com include, require, include_once e require_once, que permitem importar arquivos contendo HTML, funções e outras estruturas reutilizáveis. A diferença principal é que include gera aviso e permite que o script continue, enquanto require interrompe a execução em caso de falha.

Este capítulo foi organizado em duas partes. Primeiro, construiremos um formulário com Bootstrap para demonstrar estratégias de validação em PHP. Em seguida, separaremos a navegação e as funções auxiliares em arquivos externos, usando essa reorganização para apresentar o uso de include e require.

7.1 Por que validar formulários

Validar formulários é importante por pelo menos três razões:

  • garantir que os dados recebidos estão corretos;
  • evitar o processamento de entradas vazias ou mal formatadas;
  • reduzir riscos de segurança, como exibição indevida de conteúdo HTML ou scripts enviados pelo usuário.

É importante distinguir dois tipos de validação. ### Validação no cliente

A validação no cliente ocorre no navegador, geralmente com HTML5 e JavaScript. Ela melhora a experiência do usuário porque fornece feedback imediato. No entanto, não é suficiente por si só, pois pode ser contornada.

7.1.1 Validação no servidor

A validação no servidor é feita em PHP, após o envio do formulário. Essa etapa é a mais importante para a segurança e a confiabilidade do sistema, pois os dados são verificados no ambiente onde a lógica da aplicação realmente é executada.

7.2 Caminho lógico da validação em PHP

Antes de escrever o código, é útil compreender a sequência de processamento:

  1. o usuário preenche o formulário;
  2. o navegador envia os dados para o servidor;
  3. o PHP verifica se a requisição foi feita por POST;
  4. o PHP sanitiza e valida os dados recebidos;
  5. mensagens de erro são associadas aos campos inválidos;
  6. se tudo estiver correto, os dados são aceitos e processados.

7.3 Exemplo-base da aula

Para esta aula, utilizaremos um formulário que simula parte de um sistema acadêmico simples. A interface terá uma barra de navegação em Bootstrap e campos que permitem demonstrar vários tipos de validação.

Os dados informados serão:

  • e-mail;

  • curso;
  • turno;
  • observações.

A primeira versão deixará tudo em um único arquivo, para facilitar o entendimento inicial. Depois reorganizaremos a solução para trabalhar com include e require.

7.5 Explicando a lógica de validação

O código anterior introduz vários conceitos importantes.

7.5.1 Verificação do método de envio

A condição abaixo testa se o formulário foi enviado via POST:

if ($_SERVER["REQUEST_METHOD"] === "POST") {

Essa é uma prática recorrente em exemplos de validação em PHP, pois evita que o processamento seja feito antes do envio do formulário. O uso de $_SERVER["REQUEST_METHOD"] é consistente com a abordagem didática apresentada em materiais introdutórios sobre validação.

7.5.2 Sanitização com trim(), stripslashes() e htmlspecialchars()

A função limpar_entrada() aplica três operações:

  • trim() remove espaços em branco no início e no fim;
  • stripslashes() remove barras invertidas adicionadas;
  • htmlspecialchars() converte caracteres especiais em entidades HTML.

A função htmlspecialchars() é especialmente útil para evitar que conteúdo digitado pelo usuário seja interpretado como HTML quando exibido na página.

7.5.3 Validação de e-mail

A validação de e-mail foi feita com:

filter_var($email, FILTER_VALIDATE_EMAIL)

No contexto didático, também é relevante apresentar filter_input() como função capaz de obter e filtrar diretamente uma variável externa, como mostrado no material da aula. A documentação oficial explica que filter_input() trabalha sobre o valor bruto original recebido pela SAPI.

7.5.4 Expressões regulares com preg_match()

A linha abaixo verifica se o nome contém apenas letras e espaços:

preg_match("/^[a-zA-ZÀ-ÿ\\s]+$/u", $nome)

Esse tipo de regra é útil para campos textuais que não devem aceitar números ou símbolos arbitrários.

7.5.5 Mensagens de erro por campo

O array $erros guarda uma mensagem específica para cada campo. Essa estratégia facilita a exibição de feedback ao lado do elemento correspondente e melhora a organização do código.

7.6 Resultados esperados

Ao executar o formulário, alguns comportamentos esperados são:

  • se todos os campos obrigatórios estiverem corretos, a página exibirá um bloco de sucesso com os dados digitados;
  • se o e-mail tiver formato inválido, será exibida a mensagem “Informe um e-mail válido”;
  • se a idade estiver fora do intervalo definido, a página mostrará a mensagem correspondente;
  • se o nome estiver vazio ou com caracteres inadequados, a validação impedirá o processamento final.

Esse padrão ajuda o estudante a perceber que a validação não depende apenas do HTML, mas principalmente da lógica implementada no servidor.

7.7 Melhorando a organização do sistema

A primeira versão funciona bem para introduzir o tema, mas ainda concentra muita responsabilidade em um único arquivo. Em sistemas reais, é melhor separar partes reutilizáveis.

Os dois candidatos mais óbvios para essa separação são:

  • o menu de navegação;
  • as funções auxiliares de validação.

Essa reorganização abre caminho para apresentar include, require, include_once e require_once.

7.8 Reutilização de arquivos em PHP

O material da aula destaca que, em PHP, podemos precisar importar conteúdos, funções, classes e outras definições que estão em arquivos externos.

7.8.1 include

include adiciona e avalia um arquivo. Se o arquivo não for encontrado, o PHP gera um warning, mas o script continua sendo executado. Isso costuma ser aceitável em partes menos críticas, como um menu ou um rodapé.

7.8.2 require

require também adiciona e avalia um arquivo, mas interrompe a execução com erro fatal se o arquivo não existir. É mais adequado quando o arquivo é indispensável, como uma configuração ou um conjunto de funções essenciais.

7.8.3 include_once e require_once

As versões com _once evitam que o mesmo arquivo seja incluído mais de uma vez durante a execução. Isso é útil para impedir redefinições de funções, classes e variáveis.

7.11 Criando o arquivo de funções

7.11.1 Arquivo includes/funcoes.php 

<?php

function limpar_entrada($valor) {
    $valor = trim($valor);
    $valor = stripslashes($valor);
    $valor = htmlspecialchars($valor, ENT_QUOTES, 'UTF-8');
    return $valor;
}

function validar_nome($nome) {
    if ($nome === "") {
        return "O nome é obrigatório.";
    }

    if (!preg_match("/^[a-zA-ZÀ-ÿ\\s]+$/u", $nome)) {
        return "O nome deve conter apenas letras e espaços.";
    }

    return "";
}

function validar_email($email) {
    if ($email === "") {
        return "O e-mail é obrigatório.";
    }

    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        return "Informe um e-mail válido.";
    }

    return "";
}

function validar_idade($idade) {
    if ($idade === "") {
        return "A idade é obrigatória.";
    }

    if (!filter_var($idade, FILTER_VALIDATE_INT)) {
        return "A idade deve ser um número inteiro.";
    }

    if ((int)$idade < 16 || (int)$idade > 100) {
        return "A idade deve estar entre 16 e 100 anos.";
    }

    return "";
}

7.13 Por que usar require_once para funções

O arquivo funcoes.php contém lógica necessária para o funcionamento da página. Se ele não for carregado, várias chamadas do script deixarão de existir. Nesse cenário, require_once faz mais sentido do que include, porque interrompe a execução caso o arquivo essencial não seja encontrado. Além disso, o sufixo _once evita redefinições acidentais.

7.14 Por que usar include para o menu

Já o menu é um componente visual reutilizável. Em uma aula introdutória, ele é um ótimo exemplo de include porque mostra como repetir a mesma navegação em várias páginas sem duplicar HTML. A documentação didática do W3Schools usa exatamente esse tipo de cenário para introduzir o comando.

7.16 Comparando as abordagens

7.16.1 Tudo em um único arquivo

Vantagens:

  • mais fácil para apresentar o fluxo completo pela primeira vez;
  • reduz a quantidade de arquivos na explicação inicial.

Limitações:

  • mistura HTML, regras de validação e navegação;
  • dificulta manutenção;
  • aumenta repetição quando o sistema cresce.

7.16.2 Arquivos separados com include e require

Vantagens:

  • melhora a organização;
  • permite reaproveitar código;
  • facilita manutenção;
  • aproxima o aluno de práticas usadas em sistemas reais.

7.17 Conceitos complementares importantes

Ao ensinar validação e inclusão de arquivos, alguns conceitos adicionais ajudam bastante na compreensão do processo.

7.17.1 $_POST e $_SERVER

As superglobais $_POST e $_SERVER são centrais neste capítulo. A primeira armazena os dados enviados pelo formulário com método POST. A segunda fornece informações sobre a requisição e o ambiente do script. O uso de $_SERVER["PHP_SELF"], quando combinado com htmlspecialchars(), é uma estratégia comum para enviar os dados à própria página com mais segurança.

7.17.2 Preservação de dados digitados

Observe que os campos são preenchidos novamente com os valores já enviados. Isso melhora a usabilidade, pois o aluno percebe que não é necessário redigitar todos os dados quando apenas um campo falha.

7.17.3 Separação entre sanitização e validação

É útil mostrar ao estudante que:

  • sanitizar é preparar ou limpar os dados para uso seguro;
  • validar é verificar se os dados atendem a uma regra.

As duas etapas são complementares.

7.18 Atividade prática sugerida

Desenvolva uma pequena aplicação PHP com Bootstrap contendo:

  • um menu de navegação superior;
  • um formulário de cadastro com pelo menos quatro campos;
  • validação no servidor com mensagens de erro;
  • uma função PHP criada pelo aluno para validar um dos campos;
  • separação do menu em arquivo externo;
  • separação das funções de validação em outro arquivo.

Depois, reorganize a solução para:

  • usar include no menu;
  • usar require_once no arquivo de funções.
